# LedgerBook Lite V1.5 渐进融合型设计规格

日期：2026-08-03  
状态：待用户最终审阅  
基线：V1.4.1（`ledgerbook-lite-v1.4.1-settings-icons`）

## 1. 目标

V1.5 综合两类优秀记账产品的核心思路：

- 保持极简、快速、无干扰的主记账路径。
- 将预算、周期账单、订阅、模板、隐私和数据管理做成可启用模块。
- 默认界面只展示基础能力；高级功能由用户在“模块中心”开启。
- 保持本地优先、无账号、无广告、无理财推荐。
- 保留 V1.4.1 的多账本、多账户、收支转账、搜索、日历和原创蜡笔视觉。

V1.5 不复制其他产品的品牌、文案、界面布局或图形素材，只吸收产品机制和交互原则。

## 2. 成功标准

版本交付后必须满足：

1. 新建普通支出可在“金额 → 分类 → 保存”三个主要动作内完成。
2. V1.4.1 用户覆盖安装后，账本、账户、余额和历史账单全部保留。
3. 预算、模板、周期账单、订阅、数据管理、隐私锁均可独立启用或关闭。
4. 关闭的模块不占用首页内容区，不出现无效入口。
5. 周期任务到期后只生成待确认项目，不可未经确认直接改变账户余额。
6. 备份文件可以在空白测试数据库中完整恢复，并在恢复前自动生成安全快照。
7. PIN 不以明文保存；连续失败需要短时限流。
8. 全部迁移、规则和备份测试通过，APK 编译、签名和压缩结构校验通过。

## 3. 产品原则

### 3.1 默认简单

首次升级后只默认启用：

- 极速记账
- 预算
- 数据管理

以下模块默认关闭：

- 记账模板
- 周期记账
- 订阅管理
- 隐私锁

用户启用后才显示对应卡片和入口。

### 3.2 本地优先

所有账务、预算、模板、规则、订阅和备份元数据保存在本地 SQLite 或应用私有偏好中。V1.5 不新增登录、云同步或远端分析。

### 3.3 明确确认

任何可能改变余额、删除数据或覆盖数据库的操作，都必须显示影响范围并要求确认。

### 3.4 渐进展开

常用字段直接显示；账户、时间、记账人、标签、报销、预算归属和备注放在“更多”区域。用户仍可在设置中选择默认展开。

## 4. 信息架构

底部导航保持五项：

1. 首页
2. 日历
3. 账户
4. 统计
5. 设置

不为每个高级模块增加底部导航项，避免导航膨胀。

### 4.1 首页

固定顺序：

1. 当前账本与本月收支摘要
2. 极速记账入口
3. 预算卡（模块开启时）
4. 待处理周期项目（模块开启且存在待办时）
5. 订阅提醒（模块开启且存在即将扣费时）
6. 常用模板（模块开启时）
7. 最近账单

模块卡片支持在“模块中心”中上移、下移。账本摘要和最近账单不可隐藏。

### 4.2 设置

设置页分组：

- 模块中心
- 记账默认值
- 预算设置
- 周期与提醒
- 数据管理
- 隐私与安全
- 外观与图标
- 账本和账户管理
- 关于

所有设置项使用整行点击控件，不再使用难以点击的小型 Spinner。

## 5. 极速记账

### 5.1 紧凑记账面板

点击全局“+”后打开紧凑面板：

- 顶部：支出 / 收入 / 转账切换
- 主区域：金额输入
- 分类区域：最近使用与常用分类
- 底部：当前默认账户、保存按钮、更多按钮

普通支出默认值：

- 类型：支出
- 账户：当前账本默认账户
- 记账人：设置中的默认记账人
- 时间：当前时间，或日历页已选日期
- 计入预算：开启

“更多”展开后显示：

- 账户或转入账户
- 日期时间
- 记账人
- 标签
- 是否报销
- 是否计入预算
- 优惠金额
- 备注

### 5.2 最近分类与常用分类

分类使用频次由历史账单实时统计，不新增冗余计数表。

排序规则：

1. 用户收藏分类
2. 最近 30 天使用次数
3. 最近使用时间
4. 内置分类顺序

收藏状态保存在 SharedPreferences，键由账本 ID 与分类完整标签组成。

### 5.3 复制上一笔

在紧凑面板提供“复制上一笔”：

- 复制类型、分类、金额、账户、记账人、标签、预算属性和备注。
- 时间始终替换为当前时间或日历选中日期。
- 转账在目标账户不存在时禁止保存并要求重新选择。

### 5.4 本地短句解析

紧凑面板顶部提供可选输入框，例如：

- `午饭28微信`
- `昨天打车35`
- `工资8000工资卡`

解析器只做本地确定性规则：

- 提取第一个合法金额。
- 识别“今天、昨天、前天”和 `MM-dd` 日期。
- 按账户名称匹配账户。
- 按一级或二级分类名称匹配分类。
- 根据“工资、奖金、退款”等收入词切换为收入。

解析结果必须回填表单供用户确认，不直接保存。无法识别的文本保留为备注，不报错退出。

## 6. 模块中心

### 6.1 模块定义

模块 ID 固定为：

- `budget`
- `templates`
- `recurring`
- `subscriptions`
- `data_tools`
- `privacy_lock`

模块状态和排序保存在 `AppSettings` 的 SharedPreferences 中，不进入账务数据库。

### 6.2 开关行为

- 关闭模块只隐藏入口和首页卡片，不删除数据。
- 重新开启后恢复原数据和原排序。
- 订阅管理依赖周期记账；启用订阅时自动启用周期记账。
- 关闭周期记账但仍有订阅时，先提示订阅模块也会隐藏。

### 6.3 排序

模块中心使用“上移 / 下移”按钮，不在 V1.5 引入拖拽框架。排序只影响首页模块卡片。

## 7. 预算系统

### 7.1 预算类型

支持：

- 月度总预算
- 分类月预算

分类预算允许选择一级分类或完整二级分类标签。每个账本、每个月、每个预算范围只允许一条有效记录。

### 7.2 计算规则

预算支出只统计：

- 类型为支出
- `include_budget = 1`
- 发生时间位于预算月份

转账、收入和不计入预算的支出不参与。

总预算使用量为当月全部预算支出。分类预算使用量按分类完整标签匹配；一级分类预算汇总其所有二级分类及历史同名一级分类。

### 7.3 展示

首页预算卡显示：

- 总预算
- 已使用
- 剩余
- 使用百分比
- 本月剩余天数
- 日均可用金额

颜色状态：

- 0%–79%：正常
- 80%–99%：提醒
- 100% 及以上：超支

统计页显示分类预算执行率，按超支比例降序。

### 7.4 提醒

默认阈值为 80% 和 100%。同一账本、同一月份、同一阈值只提示一次。提示状态保存在预算记录中。

## 8. 记账模板

模板字段：

- 名称
- 类型
- 分类
- 可选固定金额
- 可选默认账户
- 可选转入账户
- 记账人
- 标签
- 是否计入预算
- 备注
- 排序
- 使用次数与最后使用时间

点击模板后打开已填充的紧凑面板，仍需用户确认保存。模板不直接改变余额。

首页最多显示 6 个模板；其余从模板管理页访问。

## 9. 周期记账

### 9.1 规则

支持频率：

- 每天
- 每周
- 每月
- 每年

支持间隔值，例如每 2 周、每 3 个月。

结束条件：

- 永久
- 截止日期
- 固定次数

规则保存后计算 `next_due_at`。

### 9.2 到期处理

到期时生成 `PENDING` 待办，不生成正式账单。用户可以：

- 确认生成
- 修改后生成
- 跳过本次
- 暂停规则

确认生成时必须在一个数据库事务中：

1. 创建账单
2. 更新账户余额
3. 将待办标记为 `CREATED`
4. 计算下一次到期时间

### 9.3 检查机制

- 应用启动和恢复到前台时检查到期规则。
- 启用提醒后使用系统每日非精确闹钟触发检查。
- 默认提醒时间为本地 09:00，可在设置中调整。
- Android 13 及以上只在用户启用通知时请求通知权限。
- 不申请精确闹钟权限。

## 10. 订阅管理

订阅是带扩展字段的周期支出规则，附加：

- 服务名称
- 计费周期
- 下次扣费日期
- 可选试用结束日期
- 可选备注

订阅页显示：

- 即将扣费
- 月均成本
- 年度折算成本
- 已暂停订阅

年度折算：

- 月付 × 12
- 季付 × 4
- 半年付 × 2
- 年付使用原金额
- 自定义周期按天数折算 365 天

订阅到期仍只生成待确认项目。

## 11. 统计升级

统计页增加时间范围选择：

- 本月
- 上月
- 本年
- 自定义区间

新增指标：

- 收入、支出、结余
- 与上一等长周期对比
- 最大单笔支出
- 高频分类
- 分类占比
- 账户资金流向
- 预算执行率

第一版图表继续使用原生 View / Canvas，不新增重量级图表依赖。

趋势数据按日或月自动聚合：

- 区间不超过 62 天：按日
- 超过 62 天：按月

同比不在 V1.5 实现；V1.5 只实现与上一等长周期的环比，避免跨年规则歧义。

## 12. 账户增强

`accounts` 增加：

- `include_net_assets INTEGER NOT NULL DEFAULT 1`
- `archived INTEGER NOT NULL DEFAULT 0`
- `credit_limit_cents INTEGER NOT NULL DEFAULT 0`

行为：

- 归档账户不出现在新建账单默认选择中，但历史账单仍显示。
- 不计入净资产的账户不进入净资产总额。
- 信用卡账户显示额度、已用额度和可用额度。
- V1.5 不允许删除存在历史账单的账户，只允许归档。

余额校准不直接覆写余额。系统生成一条特殊分类为“账户调整”的收入或支出账单，并在备注中记录校准前后金额。

## 13. 数据管理

### 13.1 CSV 导出

导出当前账本或全部账本，字段固定为：

- 账单 ID
- 账本
- 类型
- 一级分类
- 二级分类
- 金额
- 优惠金额
- 账户
- 转入账户
- 记账人
- 标签
- 报销
- 计入预算
- 备注
- 发生时间

文件使用 UTF-8 BOM，所有文本字段按标准 CSV 引号规则转义。

### 13.2 JSON 完整备份

备份包含：

- schemaVersion
- appVersion
- exportTime
- ledgers
- accounts
- transactions
- budgets
- templates
- recurringRules
- recurringOccurrences
- moduleSettings

不包含 PIN 哈希和通知授权状态。

### 13.3 数据库快照

同时提供原始 SQLite 数据库快照，保存到应用外部私有 Documents/backups 目录。

### 13.4 恢复

恢复流程：

1. 验证文件格式和版本。
2. 验证所有外键引用。
3. 自动生成当前数据库安全快照。
4. 在临时数据库完成导入和一致性检查。
5. 校验通过后替换正式数据库。
6. 失败则保留原数据库并显示具体原因。

V1.5 不支持合并恢复，只支持完整替换。

## 14. PIN 隐私锁

### 14.1 存储

- 使用随机 16 字节盐。
- 使用 PBKDF2-HMAC-SHA256。
- 迭代次数不少于 120,000。
- 只保存盐和派生哈希到 SharedPreferences。
- 不保存明文 PIN，也不写入备份。

### 14.2 行为

- 支持 4–8 位数字 PIN。
- 可配置离开应用后立即、1 分钟、5 分钟或 15 分钟锁定。
- 连续 5 次失败后锁定 30 秒；继续失败按 60 秒、5 分钟递增。
- 关闭 PIN 需要先验证当前 PIN。
- V1.5 不实现指纹和人脸解锁。

### 14.3 隐私遮挡

应用进入后台时在最近任务缩略图上显示纯色隐私遮挡层，避免金额被系统任务预览捕获。

## 15. 数据库设计

数据库版本从 1 升级到 2。

### 15.1 新表 `budgets`

- `id INTEGER PRIMARY KEY AUTOINCREMENT`
- `ledger_id INTEGER NOT NULL`
- `month_key TEXT NOT NULL`，格式 `YYYY-MM`
- `category_scope TEXT NOT NULL DEFAULT ''`，空字符串代表总预算
- `amount_cents INTEGER NOT NULL`
- `warning_percent INTEGER NOT NULL DEFAULT 80`
- `warned_80 INTEGER NOT NULL DEFAULT 0`
- `warned_100 INTEGER NOT NULL DEFAULT 0`
- `created_at INTEGER NOT NULL`
- `updated_at INTEGER NOT NULL`
- 唯一约束：`ledger_id, month_key, category_scope`

### 15.2 新表 `transaction_templates`

包含第 8 节全部模板字段，并通过外键关联账本和可选账户。

### 15.3 新表 `recurring_rules`

包含第 9 节规则字段，并增加：

- `kind TEXT NOT NULL`：`TRANSACTION` 或 `SUBSCRIPTION`
- `enabled INTEGER NOT NULL DEFAULT 1`
- `next_due_at INTEGER NOT NULL`
- `remaining_count INTEGER`

### 15.4 新表 `recurring_occurrences`

- `id INTEGER PRIMARY KEY AUTOINCREMENT`
- `rule_id INTEGER NOT NULL`
- `due_at INTEGER NOT NULL`
- `status TEXT NOT NULL`
- `transaction_id INTEGER`
- `action_at INTEGER`
- 唯一约束：`rule_id, due_at`

### 15.5 账户表迁移

使用 `ALTER TABLE` 增加第 12 节三个字段。迁移必须可重复检测列是否已存在，避免部分升级后再次启动失败。

### 15.6 索引

新增：

- `idx_budgets_ledger_month`
- `idx_templates_ledger_order`
- `idx_recurring_rules_due`
- `idx_recurring_occurrences_status_due`

## 16. 组件边界

新增组件按单一职责拆分：

- `ModuleRegistry`：模块依赖、默认状态和排序。
- `QuickEntryController`：紧凑记账状态与默认值。
- `QuickPhraseParser`：本地短句解析。
- `BudgetRepository` / `BudgetCalculator`：预算持久化与纯计算。
- `TemplateRepository`：模板管理。
- `RecurrenceCalculator`：纯 Java 下次到期计算。
- `RecurringRepository`：规则、待办和确认生成事务。
- `SubscriptionCalculator`：月均与年化成本。
- `StatisticsService`：区间聚合和环比。
- `BackupService`：CSV、JSON、快照、恢复验证。
- `PinLockManager`：PIN 派生、验证、限流和锁定状态。

Activity 只负责页面路由和组件装配，不继续把业务逻辑堆入单个 Activity。

## 17. 错误处理

统一规则：

- 用户输入错误使用明确中文提示，不显示 Java 异常类名。
- 数据库写入使用事务；任何一步失败全部回滚。
- 周期确认重复点击由唯一约束和状态检查阻止重复账单。
- 备份目录不可用时显示目标路径和失败原因。
- JSON 恢复遇到未知较新 schemaVersion 时拒绝导入。
- 预算金额、模板金额和周期金额必须大于 0。
- 账户已归档或不存在时，模板和周期任务进入“需要修复”状态，不能生成账单。

## 18. 测试策略

### 18.1 纯 Java 单元测试

- `QuickPhraseParserTest`
- `BudgetCalculatorTest`
- `RecurrenceCalculatorTest`
- `SubscriptionCalculatorTest`
- `ModuleRegistryTest`
- `PinHashRulesTest`
- `StatisticsPeriodRulesTest`

### 18.2 数据库测试

- V1 → V2 迁移保留账本、账户、余额和账单。
- 预算唯一约束和统计范围。
- 周期待办幂等生成。
- 确认周期账单时余额与状态同事务更新。
- 归档账户不进入可选账户列表。
- 余额校准生成调整账单。

### 18.3 备份测试

- JSON 导出再导入后各表记录数与关键字段一致。
- 非法外键、截断 JSON、未来版本备份均拒绝恢复。
- CSV 特殊字符、换行、逗号和引号转义正确。
- 恢复失败时原数据库哈希不变。

### 18.4 UI 契约测试

- 设置模块全部使用整行点击控件。
- 关闭模块后对应首页卡片和设置子入口不渲染。
- 紧凑记账的普通支出主要路径不超过三个主要动作。
- 周期待办必须显示确认按钮，不能存在自动落账路径。

### 18.5 CI 验证

每次 PR 必须运行：

1. V1.5 Activity/源码生成检查
2. 全部单元测试
3. Android Java 编译
4. Debug APK 构建
5. APK v2 签名校验
6. APK ZIP 完整性校验
7. V1.5 APK 和 SHA-256 产物上传

1. 数据库 V2 迁移与仓储层
2. 模块中心与设置持久化
3. 极速记账与短句解析
4. 预算系统
5. 模板系统
6. 周期规则和待办

每一步先写失败测试，再写最小实现；每批通过 CI 后再进入下一批。

## 20. 明确不在 V1.5 范围

- 云同步与多设备同步
- 自动读取银行、支付宝或微信账单
- OCR 小票识别
- 原生 Excel `.xlsx` 导出
- 多人协作账本
- 汇率联网更新和多币种折算
- 指纹或人脸解锁
- 自动未经确认生成周期账单
- 债务、报销审批、物品管理和购物清单
- 同比统计

这些能力留待 V1.6 或后续独立规格。
